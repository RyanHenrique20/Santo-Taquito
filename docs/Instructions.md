## Projeto Desenvolvimento Front-End para Web - 1ª Entrega

**Tema do Projeto**
 
Os temas deste projeto foram previamente definidos pelas equipes em sala de aula. Cada grupo deverá desenvolver um site completo baseado no tema acordado, aplicando os conhecimentos de HTML5, semântica, navegação funcional, validação de formulários e uso de recursos multimídia. Nesta primeira entrega, o CSS e Javascript não são obrigatórios.
 
**Composição do Projeto**
 
O site deverá conter 10 páginas HTML interligadas, respeitando a estrutura e as boas práticas de organização de arquivos:
 
meu-projeto/
├── index.html
├── css/
├── js/
├── img/
├── assets/
└── docs/
 
  
**Conteúdo das Pastas**
 
/css → Folha de estilos principal (style.css) com o padrão visual definido para todo o site.
/js → Scripts JavaScript utilizados para funcionalidades e interatividade.
/img → Todas as imagens utilizadas no projeto.
/assets → Arquivos complementares (fontes, PDFs, áudios, vídeos locais ou outros materiais para download).
/docs → Documentação do projeto (README, diário de bordo, relatórios e orçamento de hospedagem/domínio).
 
**Estrutura das Páginas**
 
index.html – Página inicial do site, com resumo do tema, apresentação geral e menu principal.
Páginas de conteúdo (mínimo 7) – Páginas interligadas abordando diferentes seções do tema, com uso correto de tags semânticas (<header>, <nav>, <section>, <footer>).
Página de contato – Deve conter:
Dados fictícios da empresa ou equipe responsável (nome, endereço, e-mail, telefone).
Formulário de contato validado em HTML5 (required, email, tel, date, number).
Identificação completa dos membros do grupo.
Página de orçamento (orçamento_hospedagem.html) – Relatório de comparação de provedores e domínios.
 
**Orçamento de Servidor Web e Domínio**
 
Cada grupo deverá incluir um relatório de orçamento na pasta /docs, contendo:
Três opções de hospedagem web (gratuita e/ou paga), com informações sobre espaço, largura de banda, SSL e suporte.
Três opções de registro de domínio, com valores e extensões distintas (ex.: .com, .com.br, .edu.br).
Uma tabela comparativa apresentando custos e recursos.
Um parágrafo justificando a escolha final, com base em custo-benefício e escalabilidade.
O relatório pode ser entregue em HTML ou PDF.
 
**Requisitos Técnicos Obrigatórios**
 
HTML5 e Semântica:
Uso correto das tags <header>, <nav>, <main>, <section>, <article>, <footer>.
Cabeçalhos hierárquicos (<h1>, <h2>, <h3>).
Links funcionais entre todas as páginas.
Formulário de Contato ou similar:
Campos com validação (required, email, tel, date, number).
Máscaras com pattern.
Labels corretamente associados aos campos.
Recursos Multimídia conforme necessidade do projeto:
Inserção de vídeo com <video> (poster e controles).
Inserção de áudio com <audio>.
Inserção de iframe (ex.: vídeo ou mapa incorporado).
Boas Práticas:
Código validado no W3C Validator.
Estrutura semântica e organizada.
Imagens otimizadas e corretamente nomeadas.
Navegação funcional e coerente em todas as páginas.
 
**Documentação do Projeto**

A documentação deve estar contida na pasta /docs e incluir:
README.md – Objetivos, tema e divisão de funções.
Diário de bordo – Registros de decisões, aprendizados e dificuldades.
Relatório de orçamento de hospedagem e domínio.
Evidências de testes e validações.

**Critérios de Avaliação**
 
Estrutura e organização do projeto
Aplicação correta da semântica HTML5
Validação e funcionalidade do formulário
Recursos multimídia e navegação funcional
Criatividade na resolução do problema
Documentação e orçamento de hospedagem/domínio
 
**Observações Importantes**
 
O projeto deve ter identidade visual unificada, com um único arquivo .css. (Apenas na entrega final). Para esta entrega não é obrigatório css.
Todas as páginas devem ser navegáveis entre si.
Todo o conteúdo (textos, imagens, tabelas, listas) deverá ter formatação adequada e indicação da fonte quando não for autoral.
A criatividade, clareza e coerência serão critérios de avaliação.
